# 独立质检 · 使用说明

> 2026-08-18 制定
> 背景：制作方同时担任验收方，必然有盲区——**发现盲区需要的正是它所缺失的那种视角**。
> 本文给出一套「另开一个 AI 窗口专门做质检」的做法，含可直接粘贴的提示词。

---

## 一、为什么需要，以及它补的是哪一块

这个项目已经把「每发现一个缺陷就变成一条机器检查 + 一条回归用例」做成了习惯
（52 条回归用例、三道卡口、`covercheck` 等带退出码的验收工具）。
所以**已知类型**的缺陷基本不会再漏。

真正漏掉的是另外两类。把最近一轮人工复核的 10 个问题拆开：

| 类别 | 数量 | 例子 | 独立质检能否抓到 |
|---|---|---|---|
| **有数据但没想到要查** | 3 | 片头多一句话、中间 2.8s 空白、片尾留白 | ✅ 能，属于"覆盖面"问题 |
| **语义类，规则难覆盖** | 3 | 他/它 误用、断句读着别扭、`10年`被补成`2010年` | ✅ 能，属于"语感"问题 |
| 脚本上游问题 | 3 | 缺字、口吃残留 | ⚠️ 部分能 |
| 主观 | 1 | 捂嘴动作要不要剪 | ❌ 只能人判断 |

**第一类最值得警惕**：静音间隙数据一直都在，片头对齐锚点也一直都在，
但制作方从没问过自己"除了我在查的，还有什么可能是错的"。

## 二、选谁做质检：新 Claude 窗口 vs Codex

| | 新开 Claude Code 窗口 | Codex |
|---|---|---|
| 独立性（不为自己的活辩护） | ✅ | ✅ |
| **模型差异（不同的系统性盲区）** | ❌ 同模型同偏见 | ✅ |
| 中文语感 | 与制作方相同 | 不同，可互补 |
| 能跑本机工具（Swift 二进制、抽帧） | ✅ 原生 | ✅ 但需配置 |
| 接入成本 | 0，开窗即用 | 中（需先安装，另见坑位） |
| 额度 | 同一份 | 另一份 |

**结论：先用新 Claude 窗口，语义类问题反复漏才升级到 Codex。**

理由是这两类失误的性质不同：

- **"没想到要查"是覆盖面问题**，换个没有立场的读者就能发现，**同模型完全够用**
- **"读着别扭"是语感问题**，同模型可能共享同一个盲区，**这时候跨模型才有真实增量**

按上表，前者 3 个、后者 3 个。所以新窗口先能解决一半，且成本为零。

> ⚠️ 本机目前**没有安装 Codex**（`which codex` 无结果）。要用需先装 CLI 并处理会话续接、
> 权限、工作目录三类参数问题。在语义类问题确实反复出现之前，不建议先付这个成本。

**不要用纯聊天窗口（网页版 GPT/Claude）做质检**：质检要抽帧、跑脚本、读 JSON，
纯聊天窗口做不了，你得手工搬运，那就退化成人工复核了。

## 三、三条不能省的约束

没有这三条，两个 AI 会退化成互相说好话。

**1. 打回必须带可复现的证据**
「第 5 条第 114 行，字幕是『要不然的话很』，把『很难』劈开了，依据断行规则」——
可以被复现、被反驳，也可以固化成自动检查。
「读着有点别扭」只能靠对方猜。

**2. 明确要求反驳**
每轮都要写「如果你认为我的判断是错的，直接说，并给出理由」。
要的是正确的结论，不是快速的一致。

**3. 交付用固定格式**
尤其「我没做到什么」和「需要用户决策什么」两节——
这两项最容易被省略，又最需要你知道。

---

## 四、红线（自动执行一律不允许）

- 上传/替换飞书上的成片
- 删除任何文件
- 修改脚本表
- 任何对外发布

质检窗口只负责**发现问题并报告**，不负责修，更不负责交付。

## 五、可直接粘贴的提示词

新开一个 Claude Code 窗口，工作目录设为
`/Users/tangaixue/Nutstore Files/AIGC/AI 切片短视频/AI切片短视频-剪辑`，把下面整段贴进去。

```text
你是这个项目的独立质检方。你没有参与制作，你的任务是找出制作方漏掉的问题。

【项目】把直播原片按脚本剪成短视频切片，每条出横版 1920×1080 和竖版 1080×1920，
带烧录字幕和封面。先读 项目文档.md 了解全貌。

【验收标准】全部在 06-规格/ 下，动手前必须读：
  字幕生成规范.md    文本清洗、断行、时间轴、质检的全部规则及其由来
  封面版式规范.md    封面标题锚点、限宽、自动缩字号
  视觉规格标定-横版.md / -竖版.md
  PPT插入规格.md

【本期产物】02-过程/<期次>/<两位编号>-<标题>/ 下：
  字幕.json   成片字幕与时间轴      横版.mp4 / 竖版.mp4   成片
  封面-*.png  封面                  脚本单元格.json       脚本原文（含删除线/标红样式）
  srt.log     清洗与剪切日志        预检报告.md           每处改动及其归因规则

【先跑这些确定性检查，它们是 0 成本且结果稳定的】
  cd 05-工具
  python3 test_subs.py                      # 规则回归，52 条用例
  python3 qc_subs.py <字幕.json>             # 字幕质检，[错] 必须为 0
  ./covercheck <封面-竖版.png> ../04-素材/竖版封面模板-1080x1920.png 40
  ./covercheck <封面-横版.png> ../04-素材/横版封面模板-1920x1080.png 40

【然后做机器查不了的部分——这才是你的主要价值】

一、通读每条字幕全文（字幕.json 的 lines），重点看：
   1. 指代是否正确：「他/它」指人用他、指公司或指数用它；「其他」是词不要动
   2. 断句是否符合阅读习惯：词有没有被拆开（基金/经理、很/难、过去/两年、五六/月份、AI/产业链）
   3. 数字语义：年份补全对不对？「10年以后」是时长不是2010年；「2000多点」是点位不是中证2000
   4. 有没有读不通的句子——通常是脚本里的口吃残留或漏字

二、看 预检报告.md 里每一处改动的归因。重点盯「指数名补全」「删单字残句」「删语气词」
   这三类——它们改语义或删内容，改错了往往**读起来仍然通顺**，最难发现。

三、抽帧核对（用 05-工具/vtool frame 或 measure fullframe）：
   片头第一句是否就是脚本第一句（历史上出现过片头多带一整句）
   片尾有没有多余留白
   含 PPT 的条目，PPT 是否在该出现的时候出现

【历史上真实发生过的缺陷，请确认它们没有复发】
  片头多带一整句话           片尾留白 1.3 秒         中间 2.8 秒空白
  「中证全指从2000多点」被改成「中证2000多点」        「09、10，11」糊成「1011」
  「每7到10年」被补成「每7到2010年」                「然后18年」漏补全
  「约翰伯格」应为「约翰·博格」                      封面标题压住人物 43 像素
  字幕超宽 12.0em 挤成两排                          「基金经理」「很难」「过去」被拆开

【三条要求】
1. 每个问题必须带可复现的证据：哪一条、第几行、第几秒、现在是什么、应该是什么、依据哪条规则。
   不接受「读着别扭」这类无法复现的意见。
2. 如果你认为制作方的判断是对的、或我给的标准本身有问题，直接说，并给出理由。
   我要的是正确的结论，不是附和。
3. 明确区分「这台机器做不到」和「做不到」。报告无法完成某项检查时，说清是哪一种。

【红线：以下操作一律不许自动执行】
  上传或替换飞书上的成片、删除任何文件、修改脚本表、任何对外发布。
  你只负责发现问题并报告。

【报告格式，五节缺一不可】
  一、我检查了什么     逐项列，写明命令和结果
  二、发现的问题       按严重程度排序，每条带上面要求的完整证据
  三、我没能检查什么   包括做不到的、不确定的、有意跳过的及理由
  四、需要人决策的     没有就写「无」
  五、建议制作方做什么 具体到文件和位置
```

## 六、怎么用

1. **前几轮盯紧**。人看每一轮往返，确认质检意见是有价值的、不是走过场。
   意见空洞就说明提示词里的标准还不够具体，回来改标准，而不是接着跑。
2. **质检发现的每个问题，制作方都要先写成回归用例再改**。
   这是把这轮教训固化下来的唯一办法——否则同一个问题换个形态还会回来。
3. **不要让质检窗口去修**。发现和修复分开，才保得住独立性。

---

## 七、这套机制的边界

- **主观判断它给不了可靠意见**：画面好不好看、节奏舒不舒服、内容取舍——仍然要人看
- **两个 AI 可能同时错，而且容易同向**，因为读的是同一批材料和同一份规范
- **它放大方法的好坏，不替代方法**。如果 `06-规格/` 里的验收标准本身是错的，
  质检只会更快更彻底地把错误执行下去。真正要花心思的是把标准写清楚
