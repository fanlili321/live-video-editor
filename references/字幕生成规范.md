# 字幕生成规范

> 2026-08-18 汇总
> 来源：人工剪辑流程文档「六、修正字幕」18 条 + 三份人工复核文档
> 适用：`05-工具/make_srt.py`（生成）与 `05-工具/qc_subs.py`（质检）

---

## 〇、三条总原则

**1. 脚本是文本权威，ASR 只提供时间。**
字幕文字一律来自脚本表 B 列原文，不使用语音识别结果。识别只用来给每个字打时间戳。
因此本管线**结构上不存在「字幕缺失」**——人工流程里最高频的那类问题，这里不会发生。

**2. 但专有名词的权威在词典，不在脚本。**
脚本由人工整理，同样会错。467 期脚本原文写的是「约翰伯格」，正确写法是「约翰·博格」，
一条片子里错了 6 次。凡是流程文档点名过的固定用字，**按词典强制纠正，不跟随脚本**。

**3. 质检分两级，且只拦「错」不拦「疑」。**
`[错]` 规则明确、必须修，`--stage render` 会直接拒绝渲染；
`[疑]` 含人工判断成分，只提示不阻断。**规则拿不准时宁可降级为 [疑]，不要自动改。**

## 一、文本清洗规则

| # | 规则 | 正例 | 反例（曾经犯过） | 来源 | 状态 |

| 1 | 删除脚本里的编辑批注 `（插入PPT）` | — | — | 内部 | ✅ |

| 15 | 数字后跟量词/单位的不补指数名 | `1000块钱` | `中证1000块钱` | 467/470 | ✅ |
| 16 | 清除 Markdown 转义反斜杠 | `6~7个点` | `6\~7个点` | 470 | ✅ |

> **年份补全为什么拆成三条规则**：口播里年份有三种形态——
> 「23年」带年字、「14、15年」只有末位带年字、「02、03、04、05」一个年字都没有。
> 一条规则覆盖不了，硬凑会误伤时长表达（`每7到10年`）。
> 所以是**三条互补的规则 + 一层时长护栏**，每条只管一种形态。
>
> 护栏本身也栽过一次：里面放了「后」用来挡「后10年」，
> 结果把「**然后**18年」也挡掉了——**护栏用的是单字，而语言里单字会构成别的词**。
> 现在「前/后」要求前面不是「然/之/以」。

> **规则 11b 的教训**：`2000多点` 里的 2000 是点位不是指数。
> 护栏原本只挡「后面紧跟点/亿/万」，而 `多点` 的首字是「多」，直接漏过去，
> 把「中证全指从2000多点」改成了「中证全指从中证2000多点」。
> **同一个「多」字，在断行规则里也漏了一次**（见二·3）——同源问题会在两处发作。

## 二、断行规则

单行宽度上限 **11.5 em**（约人物两臂宽度，规则②要求绝不能两排）。
在满足宽度的前提下，用动态规划挑总代价最小的断法。代价表：

| 情形 | 罚分 | 说明 | 来源 |
|---|---|---|---|
| 数字与其后量词被拆开 | **200** | `2000 / 多点`、`上世纪90 / 年代` | ⑨ |
| 专有名词前缀留在行尾 | **200** | 中证/沪深/上证/科创/创业板/恒生/标普… | ⑨ |
| **程度副词留在行尾** | **200** | 比较/非常/特别/十分/相当/更加/最为/极其 | 复核 ✅新增 |
| **框式结构的后半截起行** | **200** | 来讲/来说/而言/来看/以来/以后/以前/之后/之前/左右/上下/之间/之内/之外/为止/当中/一样/似的 | 复核 ✅新增 |
| **拉丁字母与紧邻中文之间断开** | **200** | AI产业链 / A50指数 / ETF基金 | 复核 ✅新增 |
| 行首是光杆虚词 | 70 | 的了呢吗吧着过地得**于里中上下内外间** | ⑪ |
| 行尾是「的地得」 | 40 | | 复核 |
| 行尾是单字功能词 | 60 | 就也都还很更又再把被在从对给和与向为 | 复核 |
| 单字成行 | 40 | | 复核 |

**关键实现细节**：行首虚词的判断**必须先分词**。
`过` 在黑名单里，但「过去十多年」完全正常——只看首字会误伤。
判据是「分词后首词长度是否 > 1」。

**已修复的实例**

| 反馈原文 | 根因 | 现在 |
|---|---|---|
| `多点最后呢涨到了` | 量词表缺「多」 | `中证全指呢从2000多点` |
| `于指数基金之父约翰伯格` | `于` 不在行首黑名单 | `指数基金之父约翰·博格` |
| `强的相关性也就是咱们` | 断在「比较 / 强」之间 | `有比较强的相关性` |
| `里和定投到股票基金里` | `里` 不在行首黑名单 | `储蓄里和定投` |
| `市值规模相对` / `来讲排在龙头` | 「相对来讲」被劈开，`来讲` 可以起行 | `相对来讲` 独立成行 |
| `牛市中后期的AI` / `产业链每一次呢` | jieba 把 `AI` 和 `产业链` 切成两个 token | `牛市中后期的AI产业链` |

> **拉丁-中文规则为什么可以定得这么死**：断行只在小句内部进行，标点在分句阶段就已经切开了。
> 所以不存在「买了ETF，然后…」这种跨句情形被误伤的可能。

## 三、时间轴规则

| 规则 | 做法 | 来源 |
|---|---|---|
| 字幕起止与语音对齐，误差 ≤ 0.3 秒 | 字符级 DP 对齐 + 起音吸附（前置 0.08 秒） | （5）② |
| 空隙不超过 2 秒 | 质检检查相邻行间隔 | ⑫ |
| 行首吸附只对「停顿后起句」生效 | 句中起始的行不吸附，否则会被拉偏 | 内部 |

> **不要用「几个时间点正好对上」来验证对齐**。460 期就是这么栽的：
> 3 个抽查点恰好都落在静音间隙里，看起来完全对齐，实际整条错了 6.95 秒。
> 验证要看**有符号偏差的中位数**和**无锚点长区段**两个指标。

## 四、样式规则（不属文本，但同属字幕）

| 项 | 值 | 说明 |
|---|---|---|
| 字体 | 思源黑体 CN Medium | |
| 字色 / 描边 | **黑字 + 白色外描边**（描边 = 画布宽 × 0.52%） | ⚠️ 不是白字黑边 |
| 字号 | 画布宽 × 6.95%（横版 133.5px / 竖版 75px） | 剪映「字号 12」的换算 |
| 行数 | 恒为单行 | 规则② |
| 位置 | 描边外框底边距画面底 6.94% 画面高 | |

**字色为什么是黑字白边**：含 PPT 的片子里 PPT 占比可达 86%，
幻灯片是浅色系，白字压上去读不出来。黑字白边在深色人像和浅色 PPT 上都成立。
白字 + 黑色半透明阴影方案已实测否决。

## 四·五、三道卡口（2026-08-18 起）

字幕不能出错，靠的不是「规则写得全」，而是**错误在哪一步能被拦住**。现在有三道：

| # | 卡口 | 时机 | 拦什么 | 工具 |
|---|---|---|---|---|
| 1 | **规则回归测试** | 每次跑批前，1 秒 | 改规则弄坏了别的规则 | `test_subs.py`（64 条用例） |
| 2 | **脚本预检** | 读到脚本后、切片前，10 秒 | 文本问题 + 改动归因；只报**没确认过的新形态**（每期 3~5 条） | `precheck.py` + `changesig.py` |
| 3 | 字幕质检 | 语音识别后、渲染前 | 断行、行宽、时间轴、他/它 | `qc_subs.py` |
| 4 | **剪切归因** | 生成字幕时打进 `srt.log` | 剪掉的区间里有没有话 | `make_srt.py` |
| 5 | **漏词检测** | 生成字幕后，只报不拦 | 妙记顺滑掉、脚本因此也缺的口语词 | `dropcheck.py` |

**卡口 4 的由来**：08 期「比如说」被静音剪除吞掉，**三道卡口一个都没拦住**——
预检只管文本清洗，质检只管断行和时间轴，剪切这一步只报区间不报内容。
现在每个剪切区间都会打印区内的 ASR 文本并分类（掐头/掐尾/删除线/静音），
「静音」类里出现语音直接标 ❌。

> **字宽模型必须用实测 advance**。原来中文标点按 0.5 em 算，
> 「咱们会遇到一次熊市、牛市」实测 12.000 em 却被判 11.500 放行——护栏形同虚设。
> 现值（CoreText 实测 SourceHanSansCN-Medium）：汉字与全角标点 1.000、数字 0.570、
> 拉丁 0.620、% 0.940。**`make_srt.char_width()` 与 `qc_subs.width()` 必须逐字一致。**

任何一道出 `[错]`，`batch.py` 直接中止，不产视频。

**卡口 1 的由来**：修「每7到10年」的时长护栏时，里面放了单字「后」，
把「然**后**18年」一起挡掉了——**一个修复直接制造了另一个缺陷**，
隔了一整轮人工复核才被发现。47 条规则互相牵制，靠人眼回归不现实。
每条用例都注明出自哪一轮复核，将来想删某条规则时能立刻看到它为什么存在。

**卡口 2 的由来**：字幕文本的清洗**完全不依赖音频**——脚本读出来的那一刻，
文本层面的问题就已经确定了。但质检原来跑在语音识别之后，要等 20 分钟才知道。
预检把确认点提前到开工前，且一次看完整期十几条。

预检报告会列出**每一处改动及其归因规则**，重点标出「改语义」和「删内容」两类：

```
| 规则         | 操作 | 改前 | 改后 | 上下文              |
| 指数名补全   | 增   | —    | 沪深 | 指之外，还有【】300、80 |
| 固定用字纠错 | 改   | 伯   | ·博  | 基金之父约翰【伯】格    |
| 删语气词     | 删   | 诶   | —    | 提前预测到，【诶】，这个 |
```

> 为什么要把改动摊开：最危险的错误是**改坏了但读起来通顺**。
> `中证全指从2000多点` 被改成 `中证2000多点`，不违反任何质检项、语法也通，
> 只有让人看见「指数名补全在这里加了『中证』」才可能发现。

### 但不能让人逐条看——决策指纹 + 已确认清单

摊开改动会摊出八百多条，让人扫报告和扫视频一样贵。所以再压一层：

**决策指纹**：把每处改动压成「需要独立判断对错的最小形态」。
`14 年→2014年` 和 `15 年→2015年` 是同一个决策，算一种；
`【→中证】800、` 和 `【→中证】2000多` 是两个决策，必须分开算。

归一化策略**按规则定制**，因为哪部分是噪声、哪部分是判据，每条规则不一样：

| 策略 | 含义 | 适用规则 |
|---|---|---|
| `none` | 同规则所有触发都是同一决策 | 年份补全、数字空格、书名号、固定用字纠错… |
| `number` | 判据是「数字 + 紧跟的那个字」，前文无关 | **指数名补全** |
| `class` | 上下文归一成字符类（是标点还是汉字才关键） | 删语气词 |
| `exact` | 上下文逐字保留 | **删单字残句**（删内容，风险最高） |

**已确认清单** `tools/已确认改动.json`：确认过的形态不再问第二次。
预检只报告**清单里没有的新形态**。

实测压缩效果：

| | 改动处数 | 决策指纹 | 清单过滤后需人工确认 |
|---|---|---|---|
| 467 期 3 条（首次） | 163 | 22 | 22（一次性） |
| 466 期 | 30 | — | **3** |
| 465 期 | 104 | — | **4** |

**即每期只需看 3~5 行**，每行是一句话的判断。确认后 `precheck.py --approve` 收进清单。

**安全性验证**：把「多」从量词护栏里拿掉，人为复现 `中证2000多点` 那个语义缺陷——
122 处改动里，**恰好 1 处**被标为未确认形态，正是那个缺陷：

```
❗ 指数名补全   全指呢从【（无） → 中证】2000多点
```

> 清单不会掩盖新缺陷：**它过滤的是"见过且确认对的形态"，不是"某条规则的所有触发"**。
> 规则一旦在新形态上触发，立刻浮出来。

### 卡口 5：漏词检测——两个 ASR 互为短板

**字幕文字来自脚本，而脚本是照飞书妙记的转写稿整理的。妙记会做口语顺滑**，
把它认为是口水词的成分删掉。这对会议纪要是优点，对字幕是缺陷：
观众听见「这个基金经理擅长成长风」，字幕上却只有「基金经理擅长成长风」。

467 期 08 就这样漏了 4 个「这个」，一直到人看成片才发现。实测对照：

| | 同一段音频的转写结果 |
|---|---|
| 飞书妙记 | 比如说基金经理他擅长价值风，基金经理擅长成长风… |
| 本机 Apple Speech | 比如说**这个**金经理他擅长价值发**这个**金经理善良成长风… |

**不必换 ASR 引擎，因为两份数据本来就都有，短板正好互补**：

| | 用词准确度 | 逐字保留 |
|---|---|---|
| 飞书妙记 | ✅ 财经词几乎全对 | ❌ 做口语顺滑 |
| 本机 Apple Speech | ❌「基金经理」听成「金经理」 | ✅ 一个不漏 |

而本机 ASR 每条切片本来就要跑（字幕对齐要用），**这份数据是白来的**。

**判据是词频，不是位置**。ASR 错字太多，逐位置对齐会淹没在噪声里；
但「这个/然后」这类常用词 Apple Speech 基本不会听错，计数可靠。
监控词：这个 / 那个 / 然后 / 其实 / 的话 / 一个 / 咱们 / 大家 / 就是，
ASR 比脚本多 ≥2 次才报。

**报告用脚本原文显示位置**，不用 ASR 原文——后者错字太多没法读：

```
（脚本疑缺） …边咱们呢经历过大大小小的⟨这个⟩三四次的熊市牛市…
（脚本已有） …时间呢比较短半年就结束了⟨然后⟩然后2018年呢又出现了…
```

#### 怎么把 59 处压成十几次判断

逐条问人不现实。但**它们不是 59 个独立判断**——同一个词在同一种语法位置上，
答案是一样的。所以先分类、再聚合、再滤掉映射误差：

| 类 | 判据 | 处理 |
|---|---|---|
| **A 实义成分** | `这个/那个/一个` + 名词性成分（jieba 词性 n/r/m/vn…）；`咱们/大家` | **建议补**，同类合成**一个**决策 |
| **B 话语标记** | `然后/其实/的话/就是`；`这个/那个` + 动词或形容词 | 默认忽略，只报个数 |
| **C 待定** | 其余 | 逐条报 |

判据是**后接成分的词性**，因为同一个词功能不同：

```
这个 + 名词   「这个基金经理」   指示词，删了少字   → A
这个 + 动词   「这个可能会更合适」 填充，删了更干净   → B
```

**还要滤掉映射误差**。ASR 错字多，把它的位置映射回脚本必然有偏差，两条判据能滤掉大部分假阳性：

- 插进去会**把已有的词劈开**：`中⟨这个⟩证全指`——「中证全指」是一个词
- 插进去**语法不通**：`市场上⟨这个⟩的钱`——「这个」后面不能直接跟「的/了/呢」

**实测效果**（467 期 7 条）：

| | 数量 |
|---|---|
| 原始检出 | 59 处 |
| 自动忽略（话语标记 + 映射误差） | 29 处 |
| **需要人判断** | **9 类「建议补」+ 4 条「待定」** |

同一类里所有位置答案相同，**一次决定即可**。确认要补的写进该条的 `文本修正.txt`。

> ⚠️ **只报 [疑]，绝不自动补，也不阻断**。差值大不代表都该补：
> 「然后」「那个」很多时候确实是口水词，删掉更好；
> 「这个」在「这个基金经理」里却是指示词，删了就少了字。**这个判断只能人来做。**

**验证**：拿 08 的旧脚本（漏 4 个「这个」）跑，报「脚本 2 / ASR 6，差 +4」——
**数量精确对上**；补齐后的新脚本跑，差值归零。

## 七、掐尾豁免：唯一不受任何检查覆盖的区间（470 期教训）

`make_srt.py` 对剪切区间的语音检查有一条豁免：**掐头/掐尾/删除线区间里有语音是正常的**
（那本来就不属于这条片子，或者是要删的）。这条豁免本身没错，错在它是**按区间类型**给的，
没有看区间里到底是什么。结果掐尾成了唯一不受任何检查覆盖的地方，两个方向都出过事：

| 方向 | 470 期表现 | 根因 |
|---|---|---|
| 切少了 | 08/10 片尾多出约 7 秒说话画面，**一个字幕都没有** | `cuts` 未排序：掐尾是 `append` 到末尾的，前面若有起点更晚的静音剪切，`pos = max(pos, b)` 会把整个掐尾区间吞掉。02/06/07/08/10/15/16 七条都中招 |
| 切多了 | 04/11 的**脚本末句连音带字被剪掉** | `anchor_run` 要求「连续 4 字对上」，末句被 ASR 听岔（`北证50是小微盘偏成长` → `北京五零是小薇盘篇成长`）就凑不出 4 连，`last` 退到末句之前 |

**现在的三道防线**：

1. `cuts.sort()` —— keeps 循环依赖升序，这是它的前提条件，不能靠调用顺序碰运气
2. 掐尾下限 —— `tail >= times[max(anchored)][1] + 0.35`，**任何锚定上的脚本字都不许落进掐尾区间**
   （头部不做对称处理：那里的失效方向是「多带一整句」，`anchor_run` 正是为此加的）
3. 剪切区间打印时**逐区间统计命中的脚本字**，>0 直接 `[错]`
   —— 豁免改成按**内容**给，不再按区间类型给

> 一般教训：**凡是「这一类不用查」的豁免，都要写清楚豁免的是什么、不豁免的是什么。**
> 按类型豁免会把整块区域变成盲区，而盲区里的缺陷没有任何机制会发现——
> 04/11 丢了整句收尾，三道卡口全部放行。

## 八、脚本不再经人工整理（470 期起）——补词是固定流程的一步

### 前提变了

〇·2 原本写「脚本由人工整理」。**470 期起不成立**：脚本 B 列 = 飞书妙记转写稿逐字相同，
人工只加删除线和标红。独立质检做全量比对时发现了这一点。

后果是**没有任何一层人工过滤**，转写的每一处问题都直通烧录字幕。其中最严重的一类
不是「转错了」，而是「**转丢了**」——妙记的「口语顺滑」会把话语标记直接删掉：

| 470 期 02 号实测 | 然后 | 这个 | 那 |
|---|---|---|---|
| 本地逐字 ASR（听见的） | 16 | 15 | 10 |
| 脚本（= 妙记稿） | **0** | 9 | 2 |

于是**音频里听得见、字幕里没有**。人工复核在 02/06 两条上直接指了出来。
`dropcheck.py` 每一处都找到了，却按「话语标记」自动忽略——**查到了又扔掉，比没查更糟**。

### 决策与做法（470 期定）

**全部补回，不做逐处「是口头语还是关联词」的取舍。** 理由：
1. 这不是排版取舍，是音画不符；
2. 补回来会让整条管线更准——脚本缺字 → 对齐锚点少 → 掐头掐尾越容易切错
   （03 的「北证50」被切掉，正是因为它没能锚上）；
3. 逐处判断无客观判据，且每期约 40 处，正是要消除的人工成本。

`啊/呃/嗯` 仍然删（规则①）——那些是真语气词，书面上本来就不写。

### 实现要点：定位必须靠全局对齐

`make_srt.restore_dropped()`，默认开启（`--no-restore` 可关）。

**踩过的坑，按顺序**：

| 做法 | 结果 |
|---|---|
| ① 取 10 字探针在全篇找最长匹配，4 字即命中 | **相似度不升反降**，词被插得到处都是 |
| ② 只认 ASR→脚本 diff 的 `delete` 块 | 定位对了，但太保守：02 号缺 16 个「然后」只捞回 4 个 |
| ③ 用 `equal` 块建全局位置映射，再逐处判断该位置有没有这个词 | ✅ 130 处，12/13 相似度上升 |
| ④ ③ 之后仍系统性差一格：`是主板的股票⟨然后⟩。后来呢` | 脚本有标点 ASR 没有，落点卡在标点前，**要跨过标点再插** |

> **对齐相似度是这一步的自检指标**：补的是真词，它必升（数学上 `T > M` 恒成立，
> 补 k 个全匹配的字，`2(M+k)/(T+k) > 2M/T`）。降了就是插错了位置，当场证伪，不用等人看。

### 掐头掐尾：两端都要防「切掉」

第七节记的是掐尾。**掐头是同一个病**，470 期人工复核在 03/07/08 三条上指了出来：

```
03  「北证50」被 ASR 听成「北京五零」→ 凑不出 4 连锚点 → 前 4 字被切掉
07  「有朋友问，」被听成「有盼头」    → 前 5 字被切掉
08  「北交所打」被听成「别到时候打」  → 字幕写着整句，音频却从半句开始
```

第七节里我写过「头部不做对称处理——那里的失效方向是多带一整句」，**这个理由不成立**：
`anchor_run` 防的是「多带」，但它自己会造成「切掉」，两个方向都要防。
现在按语速给 `first` 之前的未锚定字留出时间（`first * 秒每字 * 1.3`，上限 4 秒）。

### 其他随之而来的规则

| 规则 | 形态 | 出处 |
|---|---|---|
| 删跨句读口吃 | `美债它的体。体量呢` → `美债它的体量呢` | 规则⑦只管句读**后**的单字，够不着句读**前**的 |
| 合并不产生叠词 | `又出来了创业板，创业板呢` 合并时保留逗号 | 重复单元 1~4 字都要查：`科创板上市`+`上市之后呢` |
| 利率区间补 % | `国债都有四到5个点` → `4%-5%` | 三重条件：数值 ≤30、后面不跟量词、上下文有利率语义 |
| 书名不可拆行 | 《红利指数基金投资指南》12.0 em > 上限，**允许超宽** | 主力靠分词合并成单 token，`break_cost` 兜底 |

## 九、断行：已到天花板，不要再调（2026-09-10 定）

> ⚠️ **本节结论在同一天被自己的数据推翻过一次，下面记的是修正后的版本。**
> 最初写的是「程序先切、人读一遍改，手切好 5 个点」。471 期实测后不成立，见第十节。

### 为什么需要这一步

断行规则已经调到接近极限。9.2 高净值一条 934 字的片子上做过对照：

| | 行数 | 平均每行 | 与人工断在同一处 |
|---|---|---|---|
| 人工制作 | 143 | 6.6 字 | — |
| **手工凭语感切** | 133 | 7.0 字 | **87.2%** |
| 程序 | 117 | 8.0 字 | 82.1% |

手切确实更好，**但只好 5 个点**，而且**人工自己也不是满分答案**——他也在妥协
（「是不是买那种 / 教育年金」「让我印象 / 很深刻的」按「不拆词组」看同样不干净）。
两个人各自认真切同一段话，重合度大概也就 85% 上下。

真正的价值不在多出的那 5 个点，而在**手切能暴露出程序叫得出名字的毛病**。
这次一眼看出的是：**程序把动词和它的宾语切开**——

```
程序：咱们得先搞清楚他拿了 / 你的钱之后做了什么投资
人工：咱们得先搞清楚 / 他拿了你的钱之后 / 做了什么投资
```

成因是**先数够字数再下刀**：填到七八个字，刀落在哪儿就切哪儿。
人是先看这句话由哪几块组成，再决定块与块之间在哪儿分。

### 做法

`断行修正.txt`，与 `文本修正.txt` 并列放在每条片子的目录下：

```
旧行1 / 旧行2 => 新行1 / 新行2 / 新行3
```

**只许改断点，不许改字**——两边拼起来必须逐字相同，否则报错中止。
这条约束保证复核只能调整节奏，不会悄悄改内容。
文字要改走 `文本修正.txt`，两件事分开记。

`batch.py` 自动检测该文件；单独跑用 `--break-fixes`。

### 为什么记成文件，而不是直接改字幕

1. 程序的产出仍然是**可复现的基准**，改动是显式的、可 diff 的
2. 改动会**累积**——同一种毛病反复出现，就该回去修规则，而不是每期手改
3. 改完仍然过全部卡口。**复核的人也会出错**：第一次写这个文件时，
   我自己改出了一个 12.0em 的超宽行，被质检拦下了

### 成本

一期约 11,800 字脚本、1,460 行字幕。

| | 现在（程序） | 全部手切 | 程序先切+人改 |
|---|---|---|---|
| Token | 0 | 约 4~6 万 | **约 1.5~2 万** |
| 时间 | 几秒 | 20~40 分钟 | **10~15 分钟** |

### ⚠️ 一条走不通的路

「只把程序拿不准的地方交给人」——**这个思路不成立**。
实测程序「拿不准」（最优断点代价 >200）的只占 5.2%，而手切赢它的地方有 18%。
**它做错的恰恰是它自认为最有把握的地方**：把「做了」和「一个保险」切开，
它算出来代价是 0，毫不犹豫。用它自己的把握度去挑该交给人的活，
等于用那把有毛病的尺子去量。所以只能整条通读。

## 十、断行到此为止：两个认真的读者也只重合 82%（2026-09-10）

### 结论

**别再调断行规则，也别加人工断行。** 剩下的差距不是谁做错了，是断句本来没有唯一解。

471 期三条（行 2/3/7，1972 字）全程手切与程序对比，基准是人工成片 1881/1882/1885：

| | 断点重合 | 覆盖人工断点 | 耗时 |
|---|---|---|---|
| 程序 | **81.5%** | 71.0% | 几秒 |
| 全程手切（不查任何规则表） | **82.4%** | 72.7% | 2 分 22 秒 |

**只高 0.9 个点，三条里还输了一条**（02 从 81.5% 掉到 79.5%）。

两个独立来源都指向同一个数字：认真读完全文逐行断的人得 82.4%，按规则断的程序得 81.5%。
**两个认真的读者各自断同一段话，重合度就是 82% 上下。程序已经在里面了。**

人工自己也不一致——同样是「一个」，`你买一个 ⏐ 产业园区的这个REITS` 留在行尾，
`你买一个出租房方向的 ⏐ …` 又不留。**把某一版人工当满分答案去追，前提本身不成立。**

> 早先在 9.2 期一条片子上测出手切好 5.1 个点（87.2% vs 82.1%）。那是几天前的程序；
> 之后补的词典、词组不可断、停顿归零、合并上限把差距抹平了。**旧结论已失效。**

### 被证伪的一条规则，留在这里当教训

我曾从几个例子里凑出「量词短语不能被切开」（一个/一些/一种/一条 留在行尾），
在 471 期套用 14 处，自认为是在做人工复核。实测：

```
02  81.5% → 79.3%      07  74.4% → 73.4%      三条里两条变差
```

再去看人工成片，人家恰恰就是那样断的：

```
人工：你买一个 ⏐ 产业园区的这个REITS
人工：标准的中产家庭 ⏐ 它的一个        ← 整行只有「它的一个」
```

**问题不在判断失误，在做事的方式**：从几个例子凑出规则 → 套用十几处 → 不验证就交付。
这跟往代码里加规则是同一件事，只是执行者换成了人。而基准数据当时就在手边。

### 硬规矩：任何断行改动，先跑基准

`05-工具/rulecheck.py`，基准数据在 `05-工具/人工基准/`（21 条人工成片，覆盖 470 / 9.2 / 471 三期）。

```
python3 rulecheck.py                 # 当前分数
python3 rulecheck.py --save 基线      # 改动前存一份
python3 rulecheck.py --vs 基线        # 改动后逐条比较，变差的标 ↓
```

**当前基线：21 条，平均断点重合 81.0%，覆盖 72.3%。**

判读方式：

- **明显下降** → 这条改动有害，不许上
- **微升微降（±0.5pp 内）** → 在噪声里，不能据此说它有用
- 它量的是「与某一位剪辑同事的断法有多接近」，**不等于「好」**

用它复验过两条：

| 规则 | 关掉后 | 结论 |
|---|---|---|
| 词组不可断（`W_COMPOUND`） | 11 条变差、1 条变好，81.0%→80.3% | **站得住** |
| 量词短语不可断 | 三条里两条变差 | **已撤销** |

**这两条的差别我事先分不出来。区别只在于一条验证了、一条没验证。**

### 还有空间的地方在别处

断行是风格问题，没有客观对错。真正还能改进的是**有对错的**那些：

| 类别 | 471 期实例 | 成因 |
|---|---|---|
| 补词插进词组内部 | `一个体量【这个】下`、`一个普涨【然后】行情` | 补词判据比断行还松；词典在补词后才加载 |
| 百分号缺失 | `一年2到3` → `2%-3%` | 利率规则排在「数字空格」清洗之前，匹配不到带空格的「2 到3」 |
| 词典缺词 | 普涨行情、信贷部门、个人养老金账户、月薪宝 | 新题材带来新专名 |

**这些错了就是错了，值得继续修；断行不是。**
