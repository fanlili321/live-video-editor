# 竖版视频视觉规格标定

> 标定日期：2026-07-31
> 标定样本：`1782.熊市会持续多久，可以这样判断-竖版.mp4`（1080×1920 / 30fps / 10.16 Mbps / 78.4s）
> 与横版规格配套使用，见 [视觉规格标定-横版.md](视觉规格标定-横版.md)

---

## 一、版式（1080×1920，黑底）

竖版不是把横版拉伸，而是「**上标题 / 中画面 / 下字幕**」三段式，全部落在黑底上。

> **2026-08-04 定稿：中间画面一律用 16:9，不再区分是否含 PPT。**

| 区块 | 位置（top-origin px） | 说明 |
|---|---|---|
| 视频内标题 | ink 底边 = **643**，行 ink 顶到顶 = **1.25 × em**，自底向上堆叠 | 底边距视频带上沿 13px |
| 视频带 | **x=0, y=656, 1080×608** | 满宽，严格 16:9（1080/608 = 1.7763） |
| 字幕 | 描边外框底边距画面底 **569px**（即 y=1272..1351） | 紧贴视频带下沿 +9px |

### 中间画面 = 横版画面等比缩小

因为带子是 16:9，和横版输出同比例，所以**竖版和横版共用同一个裁剪框**，只是缩放系数不同：

- 横版：裁剪框 → 1920×1080
- 竖版：**同一个裁剪框** → 1080×608

用含 PPT 的样本（1806）验证，两版的人物取景完全一致：

| | 横版 | 竖版（换算到带内） |
|---|---|---|
| 人脸高 / 画面高 | 0.4443 | 0.1391 × 1920 ÷ 608 = **0.439** |
| 人脸中心 X | 0.5218 | **0.5215** |

**好处**：裁剪框只算一次；PPT 也不用为竖版单独处理（16:9 幻灯片直接铺满带子）。

### 历史记录：旧的 1.54:1 版式

2026-07-31 标定 460 期时，参照的样片用的是 1080×700（1.54:1）的带子、y=610、字幕外框 y=1319..1397、标题 em 133.5。那是**纯说话头**期数的做法，画面裁得更近。现已统一改为 16:9，460 期的竖版需要按新版式重渲。

## 二、关键发现：剪映的「字号」是相对**画布宽度**的

流程文档里横版和竖版都写「字号 12」，一直不清楚怎么换算。实测解开了：

| | 画布宽 | 字幕 em | em / 画布宽 |
|---|---|---|---|
| 横版 | 1920 | 133.5 | **6.95%** |
| 竖版 | 1080 | 75.0 | **6.94%** |

所以「字号 12」= 画布宽度的 6.95%。描边同理：横版 10px / 1920 = 0.52%，竖版 5.6px / 1080 = 0.52%。

**推论**：以后任何画布尺寸，字幕 em = 画布宽 × 0.0695，描边 = 画布宽 × 0.0052。

## 三、字幕

| 项 | 值 |
|---|---|
| 字体 / 字重 | 思源黑体 CN Medium（同横版） |
| em | **75.0px**（画布宽 1080 × 6.95%） |
| 字色 / 描边 | 纯黑 + 纯白外描边 **5.6px**，圆角 |
| 位置 | 水平居中；描边外框底边距画面底 **522px** |
| 单行上限 | 同横版 11.5 em（样片实测最宽 828px = 76.7% 画面宽） |

## 四、视频内标题（常驻全片）

| 项 | 值 |
|---|---|
| 字体 | 思源黑体 CN Bold |
| em | **133.5px** |
| 颜色 | `RGB(250,244,198)` 米黄，无描边 |
| 行距 | 行 ink 顶到顶 **166px**（1.243 em） |
| 位置 | 每行水平居中；末行 ink 底 = **600** |

## 五、画面裁剪

**与横版共用同一个裁剪框**（见第一节）。裁剪框按横版规则算：人脸高 = 输出画面高 × 0.46，人脸中心落在 (0.49W, 0.56H)，取整段人脸检测中位数，全程固定。

竖版渲染时把这个裁剪框缩放进 1080×608 的带子即可，缩放系数 = 1080 / 裁剪框宽。

## 六、竖版封面

与横版封面是**完全不同的设计**（不是同一张图裁剪）：棕底 + 虚化书架照 + 人物抠图，无云朵。

| 项 | 值 |
|---|---|
| 模板 | `素材/竖版封面模板-1080x1920.png`（从样片首帧反推，标题区纯色 `RGB(82,54,33)` 填平） |
| 标题字体 | 思源黑体 CN Bold |
| em | **139px** |
| 颜色 | `RGB(250,244,198)` |
| 行距 | 行 ink 顶到顶 **173px** |
| 位置 | 每行居中；末行 ink 底 = **769**（再往下就撞到人物抠图，抠图顶约 y=800） |

## 七、渲染命令（竖版）

```
render --src <切片> --out <成片> \
  --canvas 1080,1920 --band 0,656,1080,608 \
  --crop <与横版相同的裁剪框> \
  --subs subs.json --cover 竖版封面.png --keep <保留区间> \
  --em 75 --stroke 5.6 --bottom 569 \
  --title "行1|行2|行3" --title-em <自动> --title-pitch <1.25×em> --title-inkbottom 643
```

## 八、踩坑

**CoreText 画字不认 context 的 fillColor。** 第一版渲出来标题是黑的（黑底上完全看不见），因为我只设了 `ctx.setFillColor`，而 `CTLineDraw` 用的是属性串里的 `.foregroundColor`，缺省是黑色。字幕没暴露这个问题纯属巧合——它本来就要黑色。**颜色必须写进 NSAttributedString 的属性。**
